Relatório de Modelagem - Support Vector Machine (SVM)

1. Objetivo

Esta etapa teve como objetivo implementar e avaliar um modelo Support Vector Machine (SVM) para a previsão do desempenho acadêmico dos estudantes, tomando como referência o procedimento experimental apresentado no estudo de Yağcı (2022).

Inicialmente, buscou-se estabelecer um modelo baseline que permitisse comparar os resultados obtidos na implementação em Python com os resultados reportados no estudo original. Posteriormente, esse baseline será utilizado como referência para experimentos de otimização do modelo.

2. Dataset utilizado

Foi utilizado o dataset resultante da etapa de pré-processamento do projeto, armazenado em: 

data/processed/students_performance_processed.csv

O conjunto possui 1.854 registros. Durante o pré-processamento, as notas foram discretizadas de acordo com os intervalos utilizados no estudo de referência, resultando nas variáveis mid_term_class e final_class.

As variáveis categóricas referentes à faculdade e ao departamento também foram codificadas durante o pré-processamento, originando faculty_encoded e department_encoded.

3. Definição das variáveis

Para a implementação baseline do SVM foram utilizadas três variáveis de entrada:

  • mid_term_class - classe da nota da avaliação intermediária;
  • faculty_encoded - representação codificada da faculdade;
  • department_encoded - representação codificada do departamento.

A variável alvo utilizada foi:

  • final_class - classe correspondente ao desempenho final do estudante.

O identificador stdID não foi utilizado como atributo preditor. Da mesma forma, a nota final original não foi incluída entre as entradas, evitando que informações diretamente relacionadas ao alvo fossem fornecidas ao modelo.

4. Implementação do modelo baseline

O modelo foi implementado utilizando a classe SVC da biblioteca scikit-learn. Como o estudo original não apresenta de forma suficientemente detalhada todos os hiperparâmetros utilizados na configuração do SVM, foram mantidos os parâmetros padrão da implementação do scikit-learn nesta etapa baseline.

Foi habilitada a opção probability=True para possibilitar a obtenção das probabilidades necessárias ao cálculo do AUC. 

SVC(probability=True)

5. Estratégia de validação

Seguindo o estudo de referência, foi adotada validação cruzada com 10 folds.

Durante os testes iniciais, a utilização direta de 10 folds sem embaralhamento apresentou grande variação de desempenho entre os folds. Com a representação baseada em mid_term_class e codificação numérica das variáveis categóricas, a acurácia média obtida foi de aproximadamente 0,584.

Para tornar a divisão mais estável e preservar a proporção das classes, foi adotado StratifiedKFold com 10 divisões, embaralhamento dos registros e semente fixa: 

StratifiedKFold(
    n_splits=10,
    shuffle=True,
    random_state=42
)

A utilização de shuffle=True e random_state=42 constitui uma decisão metodológica desta implementação, permitindo maior estabilidade e reprodutibilidade da divisão dos dados.

6. Experimentos preliminares

Antes da definição do baseline, foram realizados experimentos preliminares para observar o efeito de diferentes representações dos dados e estratégias de validação.

Configuração Acurácia média
mid_term_class + Label Encoding + validação cruzada sem shuffle 0,584
mid_term_class + One-Hot Encoding + validação cruzada sem shuffle 0,404
mid_term_class + Label Encoding + validação cruzada estratificada com shuffle 0,639
mid-term original + Label Encoding + validação cruzada estratificada com shuffle 0,660

O experimento com a nota intermediária original (mid-term) apresentou acurácia superior, de 0,660. Entretanto, para o baseline de reprodução foi mantida a variável mid_term_class, considerando a etapa de discretização descrita no estudo de referência e já reproduzida durante o pré-processamento do projeto.

O teste com One-Hot Encoding foi considerado apenas um experimento preliminar e não foi adotado na configuração baseline. Novos testes envolvendo representação das variáveis categóricas poderão ser realizados posteriormente durante a etapa de otimização.

7. Métricas de avaliação

O modelo foi avaliado utilizando as seguintes métricas:

  • Acurácia (Accuracy);
  • Precisão (Precision);
  • Recall;
  • F1-score;
  • Área sob a curva ROC (AUC).

Para Precision, Recall e F1-score foi utilizada a média ponderada (weighted), considerando a distribuição desigual das classes no conjunto de dados.

Para o problema multiclasse, o AUC foi calculado utilizando a estratégia One-vs-Rest ponderada: 

roc_auc_ovr_weighted

Essas formas de agregação constituem decisões da implementação atual, uma vez que o estudo de referência não detalha suficientemente a forma de agregação das métricas para permitir uma reprodução exata desse aspecto.

8. Resultados do baseline

9. Observações sobre os resultados

Os resultados obtidos não reproduziram numericamente os valores apresentados no estudo original. Entre as possíveis fontes de diferença está o fato de o estudo de referência ter realizado seus experimentos utilizando o ambiente Orange, enquanto a presente implementação utiliza Python e scikit-learn.

Além disso, nem todos os detalhes necessários para reproduzir exatamente a configuração do SVM são especificados no estudo, como a configuração completa dos hiperparâmetros e determinados detalhes do procedimento de validação.

Durante a avaliação também foram observados avisos relacionados à precisão de determinadas classes. Em alguns folds, o modelo não realizou predições para uma ou mais classes, indicando dificuldade na classificação das classes menos representadas. Esse comportamento deve ser considerado na análise dos resultados e nos experimentos de otimização.
